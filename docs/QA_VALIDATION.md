# Πλάνο επικύρωσης

Εργαλεία για να ελέγχουμε ότι όσα φτιάξαμε δουλεύουν στην πραγματική βάση.
Demo λογαριασμός: `nikoskoukis99@gmail.com` (venue «Sport Arena»).

## Ο κύκλος

```
1. node scripts/qa/scenario.js snapshot     ← ΜΙΑ ΦΟΡΑ, πριν από όλα
2. node scripts/qa/scenario.js set <σενάριο>
3. node scripts/qa/inspect.js               ← τι ΠΡΕΠΕΙ να δείχνει το UI
4. Άνοιξε το UI και σύγκρινε — πες μου τι βλέπεις
5. node scripts/qa/scenario.js restore      ← ΣΤΟ ΤΕΛΟΣ, επαναφορά
```

## Ασφάλεια

- Κάθε έγγραφο που δημιουργούν τα scripts φέρει `_qaSeed: true`.
- Το `restore` διαγράφει **μόνο** έγγραφα με αυτό το πεδίο. Ποτέ πραγματικά δεδομένα.
- Αν ζητηθεί μείωση κάτω από τα πραγματικά έγγραφα, το script **αρνείται** αντί να σβήσει δικά σου.
- Καμία εντολή εγγραφής δεν τρέχει χωρίς προηγούμενο `snapshot`.
- Το `.snapshot.json` είναι στο `.gitignore`.

## Εντολές

| Εντολή | Τι κάνει |
|---|---|
| `scenario.js snapshot` | Αποθηκεύει plan, planType, daysRemaining, active, πλήθη |
| `scenario.js list` | Τα διαθέσιμα σενάρια |
| `scenario.js set <όνομα>` | Εφαρμόζει σενάριο |
| `scenario.js pitches <n>` | Φέρνει τα ενεργά γήπεδα στο n |
| `scenario.js athletes <n>` | Φέρνει τους αθλητές στο n |
| `scenario.js days <n>` | Ορίζει `daysRemaining` |
| `scenario.js restore` | Επαναφορά + καθαρισμός QA εγγράφων |
| `inspect.js` | Αναφορά κατάστασης + αναμενόμενο UI |

## Τι επικυρώνει κάθε σενάριο

### Δοκιμή 30 ημερών
| Σενάριο | Τι να δεις |
|---|---|
| `trial-fresh` | Top bar «Δοκιμή • 30 ημ.» · Ρυθμίσεις «Δωρεάν δοκιμή • 30 ημέρες» · **κανένα** banner |
| `trial-warning` | Dashboard banner «Η δωρεάν δοκιμή σας λήγει σε 5 ημέρες» + «Επιλογή πλάνου» · κίτρινη κουκκίδα |
| `trial-last-day` | Ενικός: «σε 1 **ημέρα**», όχι «ημέρες» |

Πριν τη διόρθωση, ο δοκιμαστικός χρήστης **δεν έβλεπε καμία προειδοποίηση** και κλειδωνόταν έξω χωρίς ειδοποίηση.

### Συνδρομή
| Σενάριο | Τι να δεις |
|---|---|
| `sub-healthy` | Πράσινο badge · χωρίς banner |
| `sub-expiring` | Banner «Η συνδρομή σας λήγει σε 3 ημέρες» + «Ανανέωση» |
| `expired` | Force logout στο login με μήνυμα λήξης |

### Ζώνες τιμολόγησης
| Σενάριο | Αναμενόμενη τιμή (μηνιαία, με ΦΠΑ) |
|---|---|
| `tier-starter` (2 γήπεδα) | €29 πλατφόρμα + ζώνη ακαδημίας |
| `tier-growth` (4) | €59 + ζώνη ακαδημίας |
| `tier-scale` (8) | €99 + ζώνη ακαδημίας |
| `academy-s` / `-m` / `-l` | +€19 / +€49 / +€89 |

Έλεγξε ότι η **Ανάλυση χρέωσης** στη σελίδα συνδρομής αθροίζει σωστά τους δύο άξονες.

### Όρια self-serve
| Σενάριο | Τι να δεις |
|---|---|
| `at-pitch-limit` (12) | «Νέο γήπεδο» → κίτρινη ειδοποίηση αντί για φόρμα |
| `over-pitches` (13) | Σελίδα συνδρομής: «Κατόπιν συνεννόησης», **χωρίς** ταμείο |
| `at-athlete-limit` (500) | «Νέος χρήστης» → μπλοκ |
| `over-athletes` (501) | Κατόπιν συνεννόησης |

Σε **όλα**: κρατήσεις, ακαδημία και αναφορές πρέπει να δουλεύουν κανονικά. Μπλοκάρει μόνο η *δημιουργία*.

### Αναβάθμιση εντός περιόδου
| Σενάριο | Τι να δεις |
|---|---|
| `upgrade-due` | Κάρτα «Εκκρεμεί αναβάθμιση» σε **dashboard και** συνδρομή, με αναλογικό ποσό για τις υπόλοιπες ημέρες |
| `paid-exact` | Πλήρωσε ακριβώς το τρέχον μέγεθος → **Νέο γήπεδο** μπλοκάρει με «Πληρωμή €X και προσθήκη». **Νέος αθλητής** ελεύθερος (δεν αλλάζει ζώνη) |
| `upgrade-clear` | Η κάρτα εξαφανίζεται |

Ο πελάτης πληρώνει τη **διαφορά** για τις ημέρες που απομένουν, όχι νέα περίοδο. Μετά την πληρωμή δεν προστίθενται ημέρες — ενημερώνεται μόνο το στιγμιότυπο, ώστε να μη ζητηθεί ξανά.

Χωρίς αποθηκευμένο `billing` (δοκιμή, ή συνδρομή πριν τη μετάβαση) **δεν χρεώνεται τίποτα αναδρομικά**.

## Γνωστές συμπεριφορές — όχι σφάλματα

**Το αποθηκευμένο `planType` δεν εμφανίζεται πια στο UI.** Ήταν στιγμιότυπο τη στιγμή της αγοράς και ξεπερνιόταν σιωπηλά όταν άλλαζε το μέγεθος — με αποτέλεσμα το top bar να λέει «Scale» ενώ η σελίδα συνδρομής «3–6 γήπεδα». Πλέον κάθε οθόνη υπολογίζει τη ζώνη από το **τρέχον** μέγεθος. Το πεδίο διατηρείται στη βάση ως καταγραφή αγοράς (admin panel, λογιστική).

**Το μπλοκάρισμα δημιουργίας είναι client-side** (γήπεδα και αθλητές γράφονται με το client SDK). Το checkout πιάνεται server-side. Για εμπορικό κανόνα αρκεί, αλλά δεν είναι φραγμός ασφαλείας.

## Άλλα scripts

`node scripts/migrate-pricing-model.js` — ξαναϋπολογίζει το `planType` κάθε venue από το μέγεθός του. Dry-run· θέλει `--apply` για να γράψει.

`node scripts/cleanup-stale-payments.js` — διαγράφει εγκαταλελειμμένες προσπάθειες πληρωμής (`status: 'pending'` παλαιότερες από 24 ώρες). Dry-run· θέλει `--apply`.

Το ίδιο γίνεται πλέον **αυτόματα** από το Cloud Function `cleanupStalePayments` (καθημερινά 03:30). Θέλει `firebase deploy --only functions`.

## Πηγή αλήθειας

`src/lib/pricing.ts` — ζώνες, εκπτώσεις, ΦΠΑ, `TRIAL_DAYS`, `SELF_SERVE_LIMITS`.

⚠️ Το `scripts/qa/lib.js` **αντιγράφει** τις ζώνες γιατί είναι απλό Node και δεν κάνει import TypeScript. Αν αλλάξεις τιμές στο `pricing.ts`, ενημέρωσε και τα δύο.
